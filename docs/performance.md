# Crabpify beta performance report

## Measurement

Generated by `benchmarks/run.sh` on 2026-08-18:

- macOS 27 arm64
- Rust 1.94.0
- Crabpify 0.1.0 release binary
- Shopify CLI 4.6.1
- 7 iterations; warm value is median

The benchmark measures equivalent version/help-style startup and process RSS. It does not claim that a complete app's own Node dev server, bundler, tunnel, or extension processes disappear.

## Results

| Metric | `cfy` | `shopify` |
|---|---:|---:|
| Cold startup | 508 ms | 2,353 ms |
| Warm startup median | **7.5 ms** | 1,866 ms |
| Peak RSS | **7.8 MiB** | 235 MiB |

A native theme watcher held idle measured **8.8 MiB RSS** in the same harness. The Shopify idle number is not comparable as a full workflow because its command lifecycle and child process behavior differ; use peak/startup as the primary comparison.

## Interpretation and limits

- The large saving is primarily from the native Rust process not loading Node at idle.
- Commands that delegate Theme Check, Hydrogen, esbuild, a framework dev server, or a tunnel will pay the memory cost of those child processes while active.
- Network latency, filesystem size, OS cache state, and installed plugin versions affect measurements.
- Re-run `benchmarks/run.sh` on the target machine before making a release claim.

The benchmark result is evidence for the architecture direction, not a promise that every Shopify project will use less total RAM under every workflow.
